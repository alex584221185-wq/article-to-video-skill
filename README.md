# article-to-video

把一篇长文章变成一套可直接发布的竖屏白板讲解视频的可复用 Skill。

不是模板集合，是一条**端到端流水线**：拉取文章 → 原创改写洗稿 → 章节拆解与分集规划 → 建项目 → 质量门禁 → 渲染归档。流程里的阈值、红线和检查器，来自一个真实跑完的 9 集系列（Grok Bot 科普系列，2026-11）。

## 为什么需要它

做系列视频最容易翻车的不是画不出来，而是：

- 换一个新窗口，上次踩过的坑又出现（字没居中、压边框、画面文字不一致）
- 引擎自带的 `--check` 报 0 error，成片仍有压框线、锚点错位
- 拿到更新过的文档，分不清「哪些讲过、哪些漏了」，把已发布的视频又重做一遍

这个 Skill 的做法是：**把规范变成可执行门禁 + 声明式布局骨架**，而不是靠记。

## 快速开始

1. 把本仓库放到 `~/.workbuddy/skills/article-to-video/`（用户级，跨项目可用）。
2. 复制 `scripts/paths.env.example` 为 `scripts/paths.env`，填一次本机的 node / python / bb-video / 输出目录路径。
3. 新开一个窗口，粘这一句：

> 按用户级 skill `article-to-video` 处理这篇文章：先拉全文，洗稿建 brief.md，用 density.py / coverage.py 拆解并只补从未讲过的章节，再用骨架建项目，渲染前 qa.mjs 与 --check 都要 0 error 并抽帧目视，最后后台渲染归档三件套。

详细流程见 [SKILL.md](SKILL.md)，分步参考在 `references/`。

```
article-to-video/
├── SKILL.md                    # 主流程（Agent 读这个）
├── README.md
├── references/
│   ├── 01-fetch.md             # S0 拉文章：飞书 / 本地 / 网页

│   ├── 03-split.md             # S2 拆解阈值、覆盖矩阵、不重制口径
│   └── 04-render.md            # S3-S5 命令、门禁、归档、探测路径
├── scripts/
│   ├── density.py              # 每章信息密度 → 分集建议
│   ├── coverage.py             # 文章章节 vs 已交付视频 → 线索对照表
│   ├── qa.mjs                  # 渲染前几何/语义门禁（0 error 才放行）
│   └── paths.env.example
└── templates/
    ├── skeleton.html           # 声明式布局助手，杜绝手写坐标偏移
    ├── script.json
    ├── brief.md
    └── plan.md                 # 分集方案模板
```

`qa.mjs` 与模板都自带，**不依赖本机另一个 skill**；外部依赖只有 `bb-video` 引擎和常规命令行工具。

## 六步

| 步 | 做什么 | 产物 |
|---|---|---|
| S0 | 拉取文章全文 | `article.md` |
| S1 | 原创改写 + 事实底稿 | `brief.md`（事实来源对照 + 屏幕文案逐条登记） |
| S2 | 按信息密度拆解、比对已交付视频 | 分集方案、覆盖矩阵 |
| S3 | 用骨架建项目、写旁白 | `index.html` / `script.json` |
| S4 | 配音 + 两道门禁 + 抽帧目视 | 0 error 记录 |
| S5 | 后台渲染、抽封面、归档三件套 | 成片 / 封面 / 字幕 |

## 实测阈值（来自 9 集系列）

- 单集容量约 **1500–2200 字 / 8–9 句旁白 / 150–175 秒**
- 三个实操共 5169 字挤进一集 159 秒 → 每个案例只剩约 53 秒，属于 3.3 倍超载
- 合规篇 2895 字做成 152.9 秒一集，密度合适
- 引擎 `--check` 不管「文字相对自己框的位置」，压框线时仍报 0 error —— 由 `qa.mjs` 补上

## 质量门禁查什么

| 码 | 问题 |
|---|---|
| E1 | 元素出安全区 |
| E2 | 文字压框线 / 横向溢出框 |
| E3 | 文字未在框内居中 |
| E4 | 同框同列文字压叠 |
| E5 | 锚点不在对应句口播里（顺序错位） |
| E6 | 屏幕文案没登记 brief.md |
| W1 / W2 | 无所属框的文字 / 一幕里过半锚点挤在句尾 |

几何检查之外仍需抽帧目视：字形观感、逐词点亮节奏、画面长时间只有标题，工具查不出。

## 注意

- 本仓库默认**私有**：包含内部工作流约定与本机路径示例。
- 内容红线：不出现作者／机构／品牌／价格；案例标教学演示；不承诺效果比例；保留境外服务可用提醒。
