# S2 · 拆解与分集规划

先用脚本量化，再做判断。脚本给线索，**最终结论要逐条比对已交付视频的 `brief.md`**。

## 1. 信息密度

```bash
python3 scripts/density.py article.md
```

输出每章：字数、可抄提示词数（`> ` 引用）、表格数、要点数、建议（一章一集 / 合并 / 拆两集）。

阈值（来自 9 集实测）：

| 章节体量 | 处理 |
|---|---|
| < 1000 字 | 信息太薄，与相邻章合并或只做图文 |
| 1500–2200 字 | **正好一集**（8–9 句旁白，150–175 秒） |
| 2500–3000 字 | 一集，但要砍掉次要分支 |
| > 3500 字 | 拆两集，按「概念 / 实操」或「低风险 / 高风险」切 |
| 3 章共 5000+ 字 | 绝不能压进一集：每章只剩约 50 秒，只剩结论没有过程 |

实例：合规篇 2895 字做成 152.9 秒一集，密度合适；三个实操合计 5169 字曾压进 ep07 一集 159.7 秒 → 每个案例仅约 53 秒，属于 3.3 倍超载。

## 2. 线索对照（哪些可能还没做过）

```bash
python3 scripts/coverage.py article.md "<已交付视频根目录>"
```

脚本读取根目录下每集的 `brief.md`，把「On-screen text」合并，然后为每章输出：
字数、核心词数、命中词数、**命中词出现在哪几集**、以及**一次都没出现过的专有词**。
另列「在任一视频里都没有命中线索的章节」作为优先核对对象；页眉与附录自动排除。

**它不下结论。** 关键词命中率受术语变体影响很大，实测过两类误判：

- 完全没做过的章节，因为「结果」「来源」这类通用词在别的集里出现过，被判成「已覆盖」；
- 讲过的章节，因为视频里换了说法（「内容审校」vs「公开资料调研」），被判成「未覆盖」。

所以判读只能靠人工，步骤：

1. 看「未命中的专有词」：如果整章的核心方法名、公式、结业标准全在里面，大概率没讲过。
2. 打开「命中词出现的那几集」的 `brief.md`，逐条看屏幕文案，确认该章**主体方法**是否真的出现过。
3. 只有「整章方法从未出现」才算漏；出现过哪怕压缩、哪怕只提一句，都算已覆盖。

实例：某章「提示词方法篇」的五要素公式、验收标准、6 类失败对照、长期规则与单次任务全没出现过 → 漏。另一集里出现过「验收标准才是完成依据」只是模板库的收尾提醒，不算讲过方法本身。

## 3. 默认口径：只补漏，不重制

**已交付的视频一律不动**：不重制、不拆分、不改编号、不下架。「做过但没讲全」（例：模板库列了 5 类而原文有 18 条、没讲故障补跑）属于压缩，**不是漏章**。

只有用户明确说「重制 / 细化 / 重做」时才改口径。

这个口径是被一句话纠正出来的：初版方案排了 4 集（含三个已做过实操的重制），用户回「之前做过的就不要做了吧，这次把上次漏掉的补上就好了」。规划前先按此收窄，能省掉整轮返工。

## 4. 编号与归档

- 新集**编号顺延**，不覆盖旧编号；旧片保留原样，必要时在简介里把旧片重定位成「总览／预告」，让新集作详解并互相引流。
- 目录：`<OUTPUT_ROOT>/<系列总文件夹>/<编号. 作品名>/`
- 三件套：`<作品名>·成片.mp4`、`·封面.png`、`·字幕.srt`
- 归档用复制，工作区 `out/` 源文件保留。

## 5. 分集方案

用 `templates/plan.md`。每集至少写清：

| 项 | 说明 |
|---|---|
| 编号 / 标题 | 与系列命名一致 |
| 对应章节 | 原文第几章，便于回查 |
| 钩子 | 前 3 秒那一句，要具体、有画面感 |
| 核心画面 | 3–5 个信息视觉（不是「讲一下 X」，是画什么） |
| 句数 / 时长 | 8–9 句，150–175 秒 |
| 与旧片关系 | 全新 / 补漏 / 旧片重定位 |

## 6. 事实核对后再动手

分集方案定稿前，回头确认 `article.md` 的章节结构与拆出来的集数一一对应，并写下「哪些章不做视频」（附录、名词速查这类信息密度低、无画面可做的，改图文或置顶）。
